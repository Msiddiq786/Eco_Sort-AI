## 1. Vision Transformer (ViT) Architecture

### Base Model: `google/vit-base-patch16-224-in21k`
- **Architecture:** Standard Vision Transformer (ViT-Base) with $16 \times 16$ patch projection.
- **Parameters:** ~86M parameters.
- **Pretraining:** Pretrained on ImageNet-21k (14 million images, 21,841 classes) without classification head.
- **Input Resolution:** $224 \times 224$ pixels, 3 channels (RGB).
- **Sequence Length:** $\left(\frac{224}{16}\right)^2 + 1 = 196 + 1 = 197$ tokens (196 image patch tokens + 1 `[CLS]` token).

### Why Vision Transformer for Waste Segregation?
1. **Global Self-Attention:** Waste items often appear deformed, crumpled, or partially occluded. Unlike standard CNNs with localized receptive fields, ViT's self-attention captures long-range spatial context and structural relationships across the entire image from the first layer.
2. **Transfer Learning from ImageNet-21k:** Pre-training on 21,000 diverse categories provides rich feature representations of materials (polymers, glass reflectivity, metal shine, paper texture, corrugated fiberboard).
3. **Complementary Ensemble Partner:** Vision Transformers develop feature representations distinct from CNNs and language-aligned models like CLIP. When fused in Phase 5 and 6, the ViT + CLIP ensemble delivers significantly higher segregation reliability.

### Classification Head Adaptation
The base checkpoint has no task-specific classification head. In `train_vit.py`, the classification head is adapted to exactly **6 classes**:

$$\text{Logits} = \mathbf{W}_{\text{head}} \cdot \mathbf{h}_{[\text{CLS}]} + \mathbf{b}_{\text{head}}$$

where $\mathbf{W}_{\text{head}} \in \mathbb{R}^{6 \times 768}$, and $\mathbf{b}_{\text{head}} \in \mathbb{R}^{6}$.

#### Fixed Class-to-Index Mapping
The mapping is deterministic and uniform across the dataset, backend, API, and frontend:

| Index | Category | id2label | label2id |
|:---:|---|---|---|
| `0` | Cardboard | `0: "cardboard"` | `"cardboard": 0` |
| `1` | Glass | `1: "glass"` | `"glass": 1` |
| `2` | Metal | `2: "metal"` | `"metal": 2` |
| `3` | Paper | `3: "paper"` | `"paper": 3` |
| `4` | Plastic | `4: "plastic"` | `"plastic": 4` |
| `5` | Trash | `5: "trash"` | `"trash": 5` |

### Dataset Preparation
Run the reproducible preparation script from `backend/`:
```powershell
python training/prepare_dataset.py --raw-dir data/raw --output-dir data --config training/config.yaml
```

This enforces:
- Presence of all 6 classes (no silent skipping).
- PIL image validation (filters corrupt/unreadable files).
- Stratified 70/15/15 split with fixed random seed (`random_seed: 42`).
- Strict zero data leakage verification ($\text{Train} \cap \text{Val} = \emptyset$, $\text{Train} \cap \text{Test} = \emptyset$, $\text{Val} \cap \text{Test} = \emptyset$).

## 3. Training Configuration & Hyperparameters

Configured in `backend/training/config.yaml`:

```yaml
model:
  checkpoint: "google/vit-base-patch16-224-in21k"
  num_labels: 6
  image_size: 224

training:
  epochs: 20
  batch_size: 32
  learning_rate: 2.0e-5
  weight_decay: 0.01
  warmup_ratio: 0.1
  gradient_clip: 1.0
  early_stopping_patience: 5
  gradient_accumulation_steps: 1
  mixed_precision: true
  metric_for_best_model: "accuracy"
  random_seed: 42
```

### Hardware Compatibility & Device Selection
The script automatically queries hardware availability:
- **CUDA:** If an NVIDIA GPU with CUDA is detected, device is set to `cuda`, tensors are pinned, and mixed precision (`torch.amp.autocast('cuda')` with `GradScaler`) is activated.
- **CPU:** If CUDA is unavailable, training initializes seamlessly on CPU with standard float32 precision.
- **Console Output:** The device is explicitly printed upon startup: `Device: CUDA` or `Device: CPU`.

From the `backend/` directory with `.venv` active:

python training/train_vit.py

## 5. Checkpointing & Checkpoint Structure

The best model is saved whenever validation accuracy improves.

Saved at: `backend/models/vit/best/`

The checkpoint directory contains:
- `model.safetensors` (or `pytorch_model.bin`) — Trained ViT weights.
- `config.json` — Hugging Face configuration including `num_labels: 6`, `id2label`, and `label2id`.
- `preprocessor_config.json` — Image processor parameters ($224 \times 224$ resize, ImageNet normalization).
- `training_metadata.json` — Hyperparameters, best epoch index, validation metrics, and timestamp.

### Loading the Trained Model in Backend Inference
The inference service in `backend/app/ml/vit_model.py` loads the model directly:

```python
from app.ml.vit_model import load_vit, predict_vit

model, processor = load_vit()
# Ready for inference: predict_vit(model, processor, pil_image)
```

## 8. Phase 5 — CLIP Foundation Model Integration

### Foundation Model Architecture: `openai/clip-vit-base-patch32`
- **Model Type:** Multimodal Vision-Language Foundation Model (Contrastive Language-Image Pretraining).
- **Vision Backbone:** Vision Transformer (ViT-Base) with $32 \times 32$ patch projection.
- **Text Backbone:** 12-layer, 512-wide Transformer with 8 attention heads.
- **Embedding Dimensionality:** 512-dimensional joint multimodal embedding space.
- **Classification Approach:** **Zero-shot inference**. CLIP does not undergo gradient fine-tuning on the waste dataset. Instead, it computes cosine similarities between image embeddings and natural-language prompt descriptions for each waste category.

### Exact Class Prompts
CLIP evaluates image similarity against 6 targeted prompts engineered for municipal waste streams:

| Class Index | Waste Category | Exact Text Prompt |
|:---:|---|---|
| `0` | `cardboard` | `"a photo of a cardboard box or cardboard waste"` |
| `1` | `glass` | `"a photo of a glass bottle or glass container"` |
| `2` | `metal` | `"a photo of a metal can or metallic object"` |
| `3` | `paper` | `"a photo of paper waste or newspaper"` |
| `4` | `plastic` | `"a photo of a plastic bottle or plastic bag"` |
| `5` | `trash` | `"a photo of general household trash or garbage"` |

### Inference & Mathematical Formulation
For an input image $\mathbf{x}$ and candidate prompt set $\{\mathbf{t}_i\}_{i=1}^6$:

1. Compute visual embedding $\mathbf{v} = f_{\text{visual}}(\mathbf{x}) \in \mathbb{R}^{512}$ and text embeddings $\mathbf{w}_i = f_{\text{text}}(\mathbf{t}_i) \in \mathbb{R}^{512}$.
2. Normalize embeddings: $\hat{\mathbf{v}} = \frac{\mathbf{v}}{\|\mathbf{v}\|_2}$, $\hat{\mathbf{w}}_i = \frac{\mathbf{w}_i}{\|\mathbf{w}_i\|_2}$.
3. Compute temperature-scaled cosine similarity logits:
   $$\text{logit}_i = \tau \cdot (\hat{\mathbf{v}} \cdot \hat{\mathbf{w}}_i)$$
4. Apply softmax across candidate classes:
   $$P_{\text{CLIP}}(c_i \mid \mathbf{x}) = \frac{\exp(\text{logit}_i)}{\sum_{j=1}^6 \exp(\text{logit}_j)}$$
5. The predicted category corresponds strictly to the argmax probability:
   $$\hat{c} = \arg\max_{c_i} P_{\text{CLIP}}(c_i \mid \mathbf{x}), \quad \text{confidence} = \max_{c_i} P_{\text{CLIP}}(c_i \mid \mathbf{x})$$

### Model Loading & Lifecycle
- **Loaded Once:** Loaded during FastAPI lifespan startup in `backend/app/ml/loader.py` (`model_registry.load()`).
- **Memory Retention:** Reused across subsequent inference requests without per-request reloading.
- **Fault-Tolerant:** If offline cache is unavailable or loading fails, `model_registry.clip_loaded` is set to `False`. The service gracefully reports `503 Service Unavailable` for direct CLIP requests (`POST /api/predict/clip`) without generating fallback or synthetic predictions.
